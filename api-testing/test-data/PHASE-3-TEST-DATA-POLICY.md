# Phase 3 Test Data Policy

## Purpose

This policy defines how test data will be created, identified and handled during Project Helix Phase 3 FHIR API testing.

## Data Source

All test data used during Phase 3 will be:

- synthetic data created specifically for testing; or
- data generated by the public HAPI FHIR test server during test execution.

No real patient or other real-world clinical information will be used.

## Synthetic Data Identification

Synthetic records will use clearly identifiable test values so they cannot reasonably be mistaken for real patient data.

FHIR resource names and identifiers will use a consistent test prefix such as:

`HELIX-TEST`

Unique values will be generated where required so that tests can be repeated safely after public-server resets.

## Credentials and Configuration

No credentials, passwords, API keys or private connection strings will be stored in the repository.

Where configuration or credentials are required locally, environment variables will be used instead.

Secrets must not appear in:

- source code
- Postman collections
- test data files
- screenshots
- test reports
- Git commits

## Public Test Environment

The HAPI FHIR public test server is a demonstration environment and may reset or remove resources.

Tests will therefore:

- create the resources they require;
- capture generated resource IDs dynamically;
- avoid relying on previously created records;
- avoid high-volume or destructive testing.

## Evidence Handling

Test evidence will contain synthetic data only.

Screenshots, API responses, logs and reports must not contain real patient information or credentials.

## Data Retention and Cleanup

Where practical, resources created during testing will be deleted after the test workflow has completed.

Because the public HAPI FHIR server may reset independently, tests must not depend on successful deletion or on the continued existence of previously created resources.

## Approval

This policy is the Phase 3 test-data handling baseline and will be followed before implementing automation that creates FHIR resources.
